# 开发说明

## 布局基准

所有坐标均为 96 DPI 下的逻辑像素，通过 `ui_px()` 换算。

| 元素 | X | Y | 宽 | 高 |
| --- | ---: | ---: | ---: | ---: |
| 窗口 | — | — | 451 | 416 |
| 用户名框 | 21 | 158 | 346 | 32 |
| 密码框 | 21 | 221 | 346 | 32 |
| 记住凭据 | 21 | 271 | 200 | 20 |
| 状态区 | 21 | 321 | 406 | 22 |
| 确定 | 21 | 360 | 201 | 32 |
| 取消 | 226 | 360 | 201 | 32 |
| 关闭 | 421 | 0 | 30 | 30 |

输入框边框由父窗口绘制，内部使用原生 Unicode EDIT。默认显示灰色描边（`#999999`），聚焦时整圈变为蓝色（`#0078D7`）；两种状态线宽均为 1 逻辑像素，圆角半径为 4 逻辑像素，不绘制底部下划线，尺寸和线宽均随 DPI 缩放。按钮使用原生 BUTTON，并通过子类化自绘；复选框仍由系统维护勾选和键盘行为。窗口内容和原生控件的客户区绘制到 32 位 DIB，再与自绘外框、阴影统一进行预乘 Alpha 合成，使用 `UpdateLayeredWindow` 显示。圆角控件形状通过四倍采样平滑，文字保留系统字体渲染。原生 EDIT 继续维护输入法、文本选择及密码遮罩；分层表面额外同步绘制插入光标。

## 状态文本

`include/credential_ui.h` 提供同步接口：

```c
void credential_ui_set_status(HWND window, const wchar_t *text);
```

在界面线程中调用；`window` 为本程序的主窗口句柄。例如在 `window_proc` 内：

```c
credential_ui_set_status(window, L"拒绝访问。");
credential_ui_set_status(window, L"");  /* 清除并隐藏 */
credential_ui_set_status(window, NULL); /* 同上 */
```

接口将文本复制到窗口自己的缓冲区，最多保留 255 个 UTF-16 代码单元。默认启动时使用空字符串；状态变化请求一次分层合成，外框和阴影遮罩继续使用缓存。

## 业务接入位置

`src/credential_ui.c` 的 `window_proc` → `WM_COMMAND` → `IDOK` 已接入请求/结果提交。用户名、密码及复选框句柄集中在 `UiState` 中。

当前 IDOK 读取并校验输入，通过 CredentialUiResult 返回；IPC 入口负责响应消息和清零。认证在原系统网络流程执行，保存由桥接在 NetUseAdd 成功后提交。接口与生命周期见 integration.md。

## 资源与构建

版本信息、图标与 manifest 统一由 `resources/app.rc` 嵌入。单一源码同时用于 x64 和 x86，架构由编译器决定。`scripts/build.ps1` 校验 GCC 目标架构，并将 Windows 路径统一成 CMake 可接受的格式。

WinPE 部署时应在实际镜像测试通用控件、字体和输入法配置。程序对较新的 DPI API 采用运行时查询；窗口外框及阴影直接通过 GDI / 分层窗口绘制，不依赖 DWM。

## 窗口外框与行为

`src/ui_frame.c` 独立负责窗口形状、边框、阴影缓存和 Alpha 合成，采用与参考项目一致的参数：

| 属性 | 设置 |
| --- | --- |
| 普通窗口样式 | `WS_POPUP`，无原生标题栏和边框 |
| 扩展窗口样式 | `WS_EX_APPWINDOW \| WS_EX_LAYERED`，保留任务栏按钮 |
| 系统判断 | `RtlGetVersion`；Build ≥ 22000 使用 G2 连续圆角，其他使用直角 |
| 窗口圆角 | 16 逻辑像素，4×4 采样，四次超椭圆 |
| 边框 | 1 逻辑像素；亮色主题 RGB(173,173,173)，暗色主题 RGB(82,82,82)，暗色不透明度 190/255 |
| 阴影空间 | 开启时四周各 32 逻辑像素，关闭时为 0 |
| 环境阴影 | 两轮可分离方框模糊，半径 18 逻辑像素，权重 26 |
| 下移投影 | 下移 4 逻辑像素，两轮可分离方框模糊，半径 11 逻辑像素，权重 44 |
| 系统阴影选项 | `SPI_GETDROPSHADOW`；设置变化时保持窗口本体的位置 |
| 激活行为 | 激活/失焦均不关闭；保存并恢复最后聚焦的控件 |

451×416 是内容本体尺寸；系统阴影开启时，96 DPI 的完整分层窗口是 515×480。所有内容和控件坐标均相对本体，原生控件的实际坐标额外加阴影留白。`WM_NCHITTEST` 排除阴影和透明圆角，顶部 65 逻辑像素（关闭按钮除外）可拖动。

原生控件处理完文本、鼠标和键盘消息后通过合并的 `WM_UI_RENDER` 请求刷新，防止一次输入触发重复合成。形状、阴影、内存 DC 和 DIB 仅在 DPI、尺寸或阴影选项变化时重建；窗口关闭后统一释放。

## 关闭图标与复选框细节

`ui_close_glyph()` 将关闭图标在 30×30 逻辑像素点击区域内居中，并以对称端点和一致线宽绘制两条对角线。`ui_checkbox()` 绘制方形 20×20 逻辑像素复选框，选中态为蓝底白勾，未选中态为白底灰色细边框；悬停、按下、键盘焦点分别处理。两者均直接对向量形状执行 8×8 采样，以免普通 GDI 斜线出现不均匀端点。

复选框外部绘图区为 24×24，控制窗口位于 (19,269)，实际方框保持在 (21,271)，标签位置和原布局一致；额外的 2 像素留白用于键盘焦点框。确定按钮默认使用蓝色，取消按钮默认底色为 `#EEEEEE`；悬停/按下使用独立的灰色反馈，离开后恢复各自的默认配色。

## 统一二进制入口

x64 / x86 的 CredentialUI.exe 均包含 GUI、IPC、会话管理器、手动挂接入口及 RCDATA 201 中的桥接 DLL；dist 只交付 EXE。CMake 先构建 DLL，再生成依赖该 DLL 的 RC 文件嵌入 EXE，支持 DLL 改动后的自动重新打包。`src/credential_bundle.c` 在启用 / 手动操作时准备内容哈希缓存；缓存包含同版 EXE 运行副本和桥接 DLL。双击 / 无参数启用管理器，重复启动返回 183 并保持现有实例运行；--preview 预览，--status / --stop 查询与停止，--attach PID / --detach PID 手动操作。--run 已移除，返回参数错误 87；内部 credential_host_main 使用空字符串表示启动模式。桥接导出在两架构统一为 ProbeStart / ProbeStop：MinGW x86 使用 --kill-at，MSVC x86 使用 bridge/exports-x86.def。

同架构检查比较当前进程与目标的 WOW64 状态，避免将 32 位指针用于 64 位目标。原生 x86 系统中双方均非 WOW64，允许正常处理。控制对象按会话与架构区分。根 build.ps1 委托 scripts/build.ps1，确保两个入口使用相同交付规则。

CTest 包含 Protocol、Runtime、GuiIpc、BridgeIdentity、Bundle、Logging 和 Environment。Logging 覆盖默认无文件、绝对路径校验、中文和空格路径、命令行错误、文件不可写及桥接远程配置传递；Runtime 同时验证关闭日志与显式开启日志的管理器生命周期。Runtime 在测试专用对象名下运行真实管理器状态机，替换进程快照与环境门禁以避免修改用户的 Explorer；覆盖启动、状态、重复实例、停止、PID 校验及实际 EXE 参数分发，并在非 WinPE 中验证真实拒绝弹窗、提示文字和退出码。Environment 用模拟系统目录与注册表读取覆盖 X: + MININT 组合、大小写、查询失败、类型错误、截断及提示行为，不修改系统注册表。Bundle 将真实交付 EXE 作为数据资源打开，在测试独占临时目录验证并发首次释放、复用、完整校验、损坏拒绝、缺失输入和不可用缓存根目录。GUI 与身份测试只使用离线输入；它们不替代真实 SMB / WinPE 接管验收。

`src/credential_environment.c` 的 credential_is_winpe 先确认系统 Windows 目录位于 X:，再检查 `HKLM\SYSTEM\CurrentControlSet\Control` 下的 SystemStartOptions 字符串是否包含 MININT（不区分大小写），任一条件失败返回 FALSE。credential_require_winpe 负责拒绝提示和错误码 50；管理器启动和手动挂接在准备日志与组件之前调用，状态、停止、撤销、预览和 IPC 不调用。该规则按本项目要求限定为 X: 系统盘。

文件诊断默认关闭；统一入口解析可选的 `--log "日志绝对路径"`，管理与手动挂接函数显式接收路径。`include/credential_log.h` 定义路径校验、UTF-8 追加和桥接配置结构；注入器通过远程参数把路径传给 ProbeStart / ProbeStop，桥接使用独立锁同步日志配置，不依赖 Explorer 的环境或当前目录。
